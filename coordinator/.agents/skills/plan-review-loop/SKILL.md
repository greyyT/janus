# Delegated planning and independent review

This skill owns task intake, current-state research, owner design decisions, execution-map negotiation, canonical planning, independent review, correction, and the final planning gate. It **does not implement the plan**. Load `../tasks/SKILL.md`, its `references/task-creation.md`, `references/research.md`, and `references/planning.md` as needed; those contracts own artifact meaning. Load the `herdr-delegation` skill for pane and first-turn mechanics. Do not infer delegation authority from a task file alone: require the user's explicit request or a matching verified grant.

## Intake and research

1. As Janus, create or refresh `.agents/tasks/<task-name>/TASK.md` from the user's request. Preserve outcome, why, scope, non-goals, acceptance, constraints, and unresolved questions. A faithful capture needs no extra approval; ask when ambiguity changes success or scope. Do not begin research without an investigable contract or planning while a consequential intake question remains open.
2. Spawn `task-researcher` in the target repository using the `herdr-delegation` launcher. The task prompt tells it to load the Tasks and research contracts, read `TASK.md`, inspect source and conventions, write **only** `CURRENT_DESIGN.md`, and put potential target decisions and its complete evidence report in a distinct `/tmp/*.md` file. No target choice, plan, TODO, or implementation. Read both its report and canonical artifact. Verify load-bearing claims against source. Return one focused research correction to the same agent if necessary; stop as `research-failed` if the foundation remains unreliable. Retain the researcher through plan review for one later evidence correction.
3. Janus classifies consequential decisions under Tasks. If none exists, record the one-line fast-path target and evidence-based reason for the eventual `PLAN.md`. Otherwise discuss each material choice with the user and record affirmative acceptance in `TARGET_DESIGN.md`; update `TASK.md` first if the decision changes its contract. Agents never accept an owner-consequential target. A blocking decision pauses planning.

## Negotiate and author the plan

4. Spawn a retained `planner` with `TASK.md`, verified `CURRENT_DESIGN.md`, and accepted `TARGET_DESIGN.md` or fast-path basis. Its first prompt tells it to load Tasks and planning contracts and write **only** a named transient `/tmp` execution map plus a separate `/tmp` report. Do not yet authorize canonical `PLAN.md` or `TODOs.md` writes. The map specifies each slice's outcome, dependencies, affected surfaces, verification and atomic commit boundaries, size, review effort, and evidence-based risk rationale.
5. Janus verifies the map against source, task, capacity of each slice, valid intermediate states, and owner decisions. Negotiate at most three substantive planner turns; questions and revisions can share a turn. Escalate owner-consequential ambiguity. Accept the exact map path explicitly; if it is lost before plan approval, restart map negotiation rather than reconstructing it from memory. The accepted map is transient review input, not the canonical plan.
6. Only after map acceptance, prompt the **same** planner to author `PLAN.md` and derive `TODOs.md`, preserving accepted slicing and effort metadata. Planner must not alter upstream contracts, STEP files, or implementation source. Read the canonical artifacts and the `/tmp` report; verify evidence and map fidelity. If source invalidates the accepted target, stop for the user (`design-reopened`).

## Independent review and routing

7. Spawn a fresh `plan-reviewer` in a separate pane, independent of research and drafting. Prompt it to load Tasks and its planning reference and review `TASK.md`, `CURRENT_DESIGN.md`, accepted target or fast-path basis, the accepted map, `PLAN.md`, `TODOs.md`, and relevant source. Do not supply the planner's transcript or private reasoning. It is read-only; require a distinct `/tmp` review file with explicit `APPROVE`, `REQUEST_CHANGES`, or `BLOCKED` and only actionable, evidenced findings classified as task-intent, research, target-design, or plan defects. Challenge slicing only for objective invalidity or new evidence, not preference.
8. Janus independently verifies each material finding and records acceptance or rejection with reason. Task-intent findings return to the user (`task-reopened`); a consequential target or accepted-map invalidation returns to the user (`design-reopened`). For a research defect, return it to the retained researcher for at most one focused correction, then reassess dependent decisions and plan premises. Send only accepted plan defects to the **same** planner; allow at most two reviewer-driven correction rounds. Reuse the reviewer for narrow verification of those findings and regressions, not another full sweep. A blocked reviewer may receive one within-scope prerequisite clarification; an all-rejected `REQUEST_CHANGES` verdict gets one evidence-based reconsideration before declaring unresolved review. Do not claim approval over an unresolved material defect.
9. Janus performs an independent final check against the contract, accepted target, source, plan and TODOs. After an otherwise approving review, one additional narrowly scoped Janus-directed correction plus narrow reviewer check may fix a specific plan-fit gap, but not reopen an exhausted review cap or owner decision. Report `approved`, `blocked`, `cap-reached`, or the reopened gate truthfully. Approval authorizes a plan, **not implementation**.

## Continuity and cleanup

Use a new inspectable `/tmp` prompt and Markdown output for each turn; keep the researcher, planner, and reviewer identities and pane IDs in the active working checkpoint. Subsequent prompts to retained agents use `herdr agent wait`, then `herdr agent prompt <name> "$(cat /tmp/<prompt>.md)" --wait --timeout 3600000`; do not resend role prompts. If interrupted mid-review, record exact pending artifact, accepted/rejected findings, correction count, agent identity, and next action; do not treat a stale or checked TODO as approval. At terminal approval or stop, close only recorded Janus-owned panes, reviewer first, planner second, researcher last. Preserve canonical task artifacts and report evidence, uncertainty, and unresolved gates; no launcher status decides review outcome.
